# T20 — Testes ponta a ponta

**Depende de:** T18, T19 · **Pacotes:** raiz (`e2e/`) · **Branch:** `task/20-e2e`

## Objetivo
Garantir com navegadores reais que uma partida completa funciona, com vários jogadores ao mesmo tempo.

## Leia antes
- `docs/arquitetura.md` §8
- `docs/especificacao-produto.md` §6.9 (exemplo de partida)

## Entregáveis
- [ ] Playwright configurado em `e2e/` com `webServer` subindo server (`GAME_TIMING_PROFILE=fast`, banco `comicle_test`) e web.
- [ ] Helpers: `createPlayer(browser, nickname)`, `drawSomething(page)` (traços via mouse), `advanceUntilPhase(page, phase)`.
- [ ] `full-match.spec.ts`: 3 jogadores, 3 quadros — cria sala, convite, temas, leitura (confirma que os quadros somem após **Começar a desenhar**), desenho, apresentação conduzida pelo anfitrião até `finished`, nova partida volta ao lobby.
- [ ] `reconnect.spec.ts`: recarregar no meio do desenho preserva o rascunho; recarregar na leitura antes de confirmar mostra os quadros de novo.
- [ ] `lobby.spec.ts`: expulsão, sala cheia, código inexistente.
- [ ] `mobile.spec.ts`: perfil de dispositivo móvel desenhando com toque.
- [ ] Job `e2e` no CI (Postgres como serviço), com upload do relatório e traces em falha.
- [ ] Script raiz `pnpm e2e` substitui o placeholder.

## Critérios de aceite
- [ ] Suíte estável: 5 execuções seguidas sem falha intermitente localmente.
- [ ] Tempo total da suíte no CI abaixo de 5 minutos.

## Notas
- Use contextos separados (`browser.newContext()`) para cada jogador — cada um com seu `localStorage`.
- Prefira seletores por papel e texto acessível (`getByRole`), o que também valida a acessibilidade.
